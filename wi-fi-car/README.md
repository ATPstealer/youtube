# Wi-Fi Car

Машинка на Raspberry Pi 4: два мотора с энкодерами, камера. Управляется из браузера по Wi-Fi: видео + кнопки/клавиатура.

## Запуск

На Pi:

```bash
sudo apt install python3-flask python3-rpi.gpio python3-opencv python3-numpy rpicam-apps
python3 app.py                      # http://<ip-pi>:5000
```

Флаги:

- `--config other.ini` — другой конфиг
- `--port 8080` — другой порт
- `--test-motor-speed 1` — прогнать калибровку моторов (шаг ШИМ 1%), выводит таблицу PWM → тики/с
- `--test-camera` — проверить, что камера отдаёт кадр
- `--test-encoders` — счётчики энкодеров в реальном времени (крутить колёса руками, Ctrl+C — выход)

Управление: `W A S D` — ехать, `Space` — стоп, `[` `]` — скорость, `F` — полный экран. На телефоне — кнопки на экране.

## Файлы

| Файл | Что |
|---|---|
| `app.py` | Flask: страница, видеопоток, API (`/control`, `/trim`, `/status`, `/logs`), тестовые режимы |
| `motor_driver.py` | Низкий уровень: GPIO, ШИМ, счёт тиков энкодеров |
| `car_controller.py` | Езда прямо: калибровка + синхронизация колёс по энкодерам |
| `camera_driver.py` | Камера → JPEG. GStreamer, иначе `rpicam-vid`, иначе заглушка «MOCK CAMERA» |
| `config.ini` | Все настройки (пины, коэффициенты, камера, UI). Правишь руками, перезапускаешь |
| `settings.json` | Trim из UI. Создаётся сам, в git не нужен |
| `templates/`, `static/` | Веб-интерфейс |
| `scheme/SCHEME.MD` | Распиновка, питание, комплектующие, фото |
| `SPEED.MD`, `speed.png` | Калибровочная таблица моторов |

## Как едет прямо и почему так

Два одинаковых мотора на одном ШИМ крутятся с разной скоростью, машину уводит. Решение в три слоя:

1. **Калибровка (feed-forward).** `--test-motor-speed` меряет тики/с каждого мотора на каждом ШИМ. Таблица зашита в `car_controller.py`. Скорость в % → нужные тики/с → свой ШИМ для каждого колеса по интерполяции. Уже почти прямо.
2. **Синхронизация (PI-регулятор, `[drive] sync`).** 20 раз в секунду сравнивает **суммарный путь** колёс с начала движения (не мгновенную скорость). Отставшее колесо догоняет, а не просто выравнивает скорость, поэтому рывок одного колеса на старте не превращается в постоянный поворот. Поправка ограничена `max_correction`, ШИМ не ниже `min_pwm`, чтобы регулятор не мог остановить колесо.
3. **Trim (ползунок в UI).** Энкодер видит вал мотора, а не землю. Если колёса разного диаметра, одинаковые тики ≠ одинаковый путь, регулятор этого не видит. Trim задаёт, какое соотношение тиков L/R считать «прямо». Подбирается один раз на глаз, сохраняется в `settings.json`.

Защита: если одно колесо перестало давать тики (`stall_time`) или ошибка растёт при максимальной поправке (`diverge_*`, например перепутаны энкодеры), синхронизация выключается и машина едет только по калибровке. В статусе UI будет `fault: ...`.

Повороты — на месте, колёса в разные стороны, тоже с синхронизацией.

## Если что-то не так

- **Мотор крутится не в ту сторону** → `left_reverse` / `right_reverse` в `config.ini`.
- **Виляет** → уменьшить `kp`. **Долго выравнивается** → увеличить `kp`. **Раскачка** → уменьшить `ki`.
- **Колесо встаёт на малой скорости** → поднять `min_pwm` (мёртвая зона моторов до ~14% в воздухе, под нагрузкой больше).
- **Сразу `fault: diverging`** → энкодеры подключены к чужим моторам.
- **Сменил моторы** → заново `--test-motor-speed 1`, обновить `calibration_points` и `max_tps` в `car_controller.py`.
- **Энкодер на GPIO14/15 шумит при загрузке** → выключить serial console (`raspi-config` → Interface → Serial), это пины UART.
- **Вместо видео «MOCK CAMERA»** → камера не нашлась, смотреть логи (кнопка логов в UI).
